# Голосовые идеи в Obsidian

Vault: `/home/artem/repos/obsidian`. Новые записи находятся в `Hermes/`.
Голосовые исходники сохраняются в `sources/`, оформленные мысли в `ideas/`,
связанные темы в `wiki/`, планы и задания в `builds/`. `index.md` открывает
навигацию. `log.md` фиксирует изменения. Существующие папки vault не импортируются.

Просто наговаривайте мысль: служебная фраза «сохрани» не нужна. Можно сказать:

- «Дополни предыдущую мысль: …»
- «Исправь в моей идее: бюджет не 1000, а 2000».
- «Что я говорил о …?»
- «Составь план по предыдущей идее».

Команда «реализуй» пока сохраняет задание в Obsidian: произвольный код не
запускается. Выбор репозитория и исполнитель разработки — отдельный этап.
Вопросы не создают новых идей; их исходная расшифровка остаётся в sources.
Если непонятно, какую мысль дополнять, агент уточнит цель.

Подтверждение «сохранил» формирует сервер только после записи файлов.
Если возник конфликт с ручной правкой, исходник остаётся, а обновление требует
проверки. В архиве соответствующей записи находятся knowledge-context.json,
knowledge-proposal.json и knowledge-result.json. В knowledge-state/knowledge.sqlite3
хранятся журнал применения и предыдущие версии. При рестарте незавершённое
применение продолжается только если файлы не были изменены вручную. Конфликтные
операции автоматически не перезаписываются; их надо разобрать по журналу.
Обновление нескольких файлов не является мгновенно атомарным для Obsidian.

## Подключение vault

Docker Compose использует `OBSIDIAN_HOST_PATH` (по умолчанию указанный выше путь)
и `OBSIDIAN_GROUP_ID` (по умолчанию 1000). Backend остаётся непривилегированным
пользователем; дополнительная группа обеспечивает совместное редактирование.
Перед первым запуском от владельца vault:

```sh
mkdir -p /home/artem/repos/obsidian/Hermes
chmod 2770 /home/artem/repos/obsidian/Hermes
```

В новых каталогах наследуется группа владельца, файлы создаются с режимом 0660.
Не менять владельца всего vault. Для отключения обработки знаний использовать
`VOICE_KNOWLEDGE_ENABLED=false`. Требуется `VOICE_AGENT_PROVIDER=codex` и работающий
host-side agent service. Credentials остаются в прежних локальных env-файлах.

## Источники архитектуры

- [Karpathy LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f):
  постоянная база знаний поверх исходников.
- [cerebro](https://github.com/andresbuonaiuto/cerebro), commit
  `d52cbffd8e795a1297a1cc2b8914c61f671432f3`: организация источников и тематических
  страниц, работа с противоречиями.
- [llm-wiki ingest](https://github.com/ddsyasas/llm-wiki/blob/e8dd69ebba0dc7c395c1b8217bb1c30c14e8c84c/packages/core/src/ingest.ts):
  получение контекста и разделение предложения изменений от записи.
- [Rambler](https://github.com/BerkeleyHCI/rambler): оформление смысловых частей речи.

Реализация Python и промпт написаны для Hermes Echo; сторонний код не скопирован.
Дополнительные приложения и плагины Obsidian не требуются.
